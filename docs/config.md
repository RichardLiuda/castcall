# 配置

## site.json

`instance/site.json`，只写想改的字段就行，没写的用默认值（`server/config.py` 里的 `DEFAULTS`）。改完刷新页面生效，不用重启服务。完整示例见 `examples/site.example.json`。

**不要往 `site.json` 里放密钥。** 它的一部分会原样发给浏览器（`/site.js`）。token 放 `.env`。

### mode

| 值 | 效果 |
|---|---|
| `auto`（默认） | 只有 1 个团时按单团显示，多于 1 个按多团显示。工作组（`kind: "crew"`，摄影 / 后勤 / 妆娘…）不算独立团，所以「一部作品 + 摄影后勤」仍然是单团 |
| `single` | 强制单团显示：页首是这部的封面和人数，角色直接铺开。有工作组时，工作组列在已定阵容下面 |
| `multi` | 强制多团显示。开头只建了一个团、后面还要加团时用它，界面不会跳来跳去 |

### event：活动信息

| 字段 | 例子 | 说明 |
|---|---|---|
| `title` | `"xx 社 冬季团建"` | 页面标题、海报标题 |
| `subtitle` | `"成员一览"` | 标题旁边的小标签 |
| `date` | `"2026-12-12"` | 显示用的文字，随便写 |
| `startAt` | `"2026-12-12T11:00:00+08:00"` | 倒计时的目标时间，**一定要带时区**。留空不显示倒计时 |
| `endAt` | `"2026-12-12T22:00:00+08:00"` | 过了这个时间倒计时消失。留空就是开场后 12 小时 |
| `location` | `"某某公园"` | 抬头的地点标签 |
| `organizer` | `"xx 社"` | 目前只存着，留给模板二次开发用 |
| `contact` | `{"label":"微信","value":"abc123"}` | 缺人看板底部的联系方式，留空不显示 |

### signup：报名

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉后所有「报名」按钮消失 |
| `opensAt` / `closesAt` | `""` | 报名开放时间段（带时区）。不在时间段内，报名按钮消失，接口也拒收 |
| `contactLabel` | `"微信"` | 报名表第二个输入框的名字 |
| `contactPattern` | `""` | 可选的校验正则，前后端都会用。QQ 号：`[1-9][0-9]{4,11}`；邮箱：`[^@\s]+@[^@\s]+` |
| `note` | 「提交后等审核…」 | 报名表底部的小字 |
| `fields` | `[]` | 除了 CN 和联系方式，报名还要填什么。见下 |

#### 报名额外要填的（`fields`）

团长在建站时选（网页向导第 4 步，或 `init.py --fields`），建好后在后台工具条「报名表」里随时改。每一项都能设成选填或必填：

| key | 题目 | 报名人看到的 |
|---|---|---|
| `height` | 身高 | 数字，cm（100–230） |
| `age` | 年龄 | 数字，岁（10–80） |
| `gender` | 性别 | 女 / 男 / 其他 三个按钮 |
| `sample` | 样片 | 传一张图（浏览器先压到长边 1600），**只有登录后台才看得到** |
| `city` | 所在城市 | 一行文字 |
| `experience` | 出过的角色 | 一行文字 |
| `note` | 想说的话 | 一段文字 |
| `q1`…`q6` | 自定义 | 一行文字，题目自己写，最多 6 道 |

```json
"fields":[{"key":"height"},{"key":"sample","required":true},{"key":"q1","label":"想出的妆面","type":"text"}]
```

没写 `required` 就是选填。`init.py --fields "身高,样片*,年龄,性别,想出的妆面"`：逗号分隔，`*` 结尾是必填，认不出的字当成自定义题。

- 答案存在报名记录里，后台「审核」每条报名下面显示一行（样片是缩略图）。
- 去掉某一项不会删已经收到的答案；自定义题改动后，旧答案仍按原来的 key 对应。
- 接了 Notion 的话，报名库里加一列「补充信息」（文本），会写进一行汇总；没有这一列也照常同步。
- 样片的上传频率见 `limits.sample`。

单个团暂停报名：在后台的团信息里改，或在名册里给团加 `"signup":"closed"`。

### notice：招募须知

要求 / 不接受 / 补充 / 风险写在一处，单团页、报名表、缺人看板三处自动复用（后台工具条「招募须知」）。

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 总开关。关掉时三处展示和没有这个功能时完全一样 |
| `lead` | `""` | 一句话定调，最多 40 字，超出截断；留空不显示 |
| `items` | `[]` | 条目列表，最多 12 条，超出的服务端直接丢掉 |
| `items[].kind` | — | 只能是 `must`（必须 / 卡什么）、`deny`（不接受）、`warn`（提醒 / 风险）、`info`（补充说明）；其他值整条丢掉 |
| `items[].text` | — | 最多 80 字，超出截断。不做富文本，`<` `>` `&` 原样转义显示 |

```json
"notice":{
  "enabled":true,
  "lead":"自然感团片，不修厚涂",
  "items":[
    {"kind":"must","text":"挡脸出图"},
    {"kind":"must","text":"16+ / 妆造 / 表情管理在线"},
    {"kind":"warn","text":"外景，确保自己受得了"},
    {"kind":"info","text":"十一月出分镜，可以一起改"},
    {"kind":"deny","text":"低龄、精彩人、预算不足、瓜人、公主病"}
  ]
}
```

- **单团页**：默认只显示前 3 条，按 `must → warn → deny → info` 的优先级取（同一 kind 内保持原顺序），超出的折叠在「查看全部 N 条」后面；展开后按 `items` 原始顺序全部铺开。折叠状态存在 `sessionStorage`，同一次会话内不会自动收起。手机宽度（< 640px）折叠时只显示前 2 条。
- **报名表**：只显示 `must` 和 `deny`，`must` 优先占位凑够 4 条，被挤掉的在「还有 N 条，见页面须知」里体现；`info` 不出现在这里。
- **缺人看板**：底部一行，`must`/`deny` 各最多取 2 条，用 `·` 连接，`deny` 前面加 `✕`。
- `site.json` 整段 `merge()` 是深合并，但 `items` 是数组，整体替换（改一条也要把其余条目一起写回去），不是逐条合并。

### guestbook：留言区

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉后留言区整块消失 |
| `moderation` | `"post"` | `post`：先显示，后台可隐藏。`pre`：后台通过后才显示 |

### photos：成员本人照片

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 开了以后，已定席位的成员能在自己角色的详情卡里点「上传我的照片」 |
| `moderation` | `"pre"` | `pre`：后台「审核 → 照片」通过后才显示。`post`：先显示，后台可撤下 |

这两项也能在后台「站点素材」面板里改。上传要填 CN，必须和席位上的成员名一样——这只防传错席位，不是身份验证（成员名本来就公开），所以公开站点建议保持 `pre`。

- 浏览器先把照片缩到长边 1600、转成 JPEG 再上传（顺带去掉 EXIF 里的定位），服务器上限 6 MB；频率限制见 `limits.photo`。
- 照片按席位 id 绑定：同一席位新照片通过后，旧的自动变成「已换新」；席位换了人，旧照片不会挂到新人头上。
- 待审 / 被拒的照片文件不公开，只有登录后台才能打开。
- 展示：单团页的大卡用照片当主图，角色立绘缩成右下角的小圆徽；多团的胶囊右侧那条图换成照片。详情卡大图默认是本人照片，左上角可以切回角色立绘。

### poster：一图流

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉后后台没有「生成一图流」按钮 |
| `slug` | `"castcall"` | 导出图片的文件名前缀 |
| `hero` | `""` | `uploads/brand/` 里的一张大图，铺在海报标题和底部 |

### brand：品牌

| 字段 | 说明 |
|---|---|
| `logo` | `uploads/brand/` 里的图片文件名，显示在标题前 |
| `accent` | 主题色，如 `#e6b35a`，用在虚线和装饰色上 |
| `favicon` | `uploads/brand/` 里的图标文件名；留空用内置图标 |

logo、favicon、海报大图在后台工具条「站点素材」里上传 / 更换 / 恢复默认（文件存进 `instance/uploads/brand/`，文件名自动写回这里，不用重启）；也可以手动放文件再改这几个字段。封面和立绘在团 / 角色的编辑框里上传。

### server

| 字段 | 默认 | 说明 |
|---|---|---|
| `host` / `port` | `127.0.0.1` / `5510` | 也可以用环境变量 `CASTCALL_HOST` / `CASTCALL_PORT` |
| `trustProxyHeader` | `""` | 见 [deploy.md](deploy.md#客户端-ip)。**直接暴露在公网时必须留空** |
| `sessionDays` | `7` | 登录有效期（天） |

### limits：频率限制

每个 IP 在 `windowSec` 秒内最多：`login` 次密码错误、`signup` 次报名、`guestbook` 次留言、`photo` 张本人照片、`sample` 张报名样片。默认 600 秒内 5 / 8 / 8 / 6 / 10。

### notion

列名映射和同步频率，见 [notion.md](notion.md#列名对不上)。

## 名册格式（roster.json）

```json
{"groups":[
  {"name":"示例作品 A","color":"#e07a5f","cover":"3f2a1b4c5d6e.jpg",
   "lead":"阿杏","contact":"微信 abc","note":"校服主题，两点东门集合",
   "kind":"cast","signup":"open","cover_focus":[0.1,0.2,0.9,0.5],
   "members":[{"id":"r1a2b3c4","character":"主角","member":"小鹿"},
              {"id":"r5d6e7f8","character":"学生会长","member":""}]}
]}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✓ | 团名，不能重复，少于 60 字 |
| `color` | ✓ | `#rrggbb` |
| `members` | ✓ | 席位列表。`character` 和 `member` 至少有一个；`member` 为空就是空缺 |
| `cover` | | `uploads/covers/` 里的文件名（后台上传会自动填） |
| `kind` | | `cast`（默认，角色团）或 `crew`（工作组：不配立绘，卡片写「负责」） |
| `lead` / `contact` / `note` | | 团长、咨询方式、说明，显示在展开后的席位上方 |
| `signup` | | `closed` 时这个团不接受报名 |
| `cover_focus` | | 海报裁封面时必须完整露出的区域 `[x0,y0,x1,y1]`（0–1），见 [poster.md](poster.md) |

`id` 由服务器自动补，`count` 和 `updatedAt` 也是自动维护的。

立绘不在名册里，在 `uploads/map.json`：`{"团名|角色名":"portraits/xxx.jpg"}`。后台改团名、角色名时会自动搬过去；手改 `roster.json` 的话要自己改这里。

## 单团 / 多团

数据结构完全一样：单团就是只有一个团的名册。区别只在呈现：

| | 多团 | 单团 |
|---|---|---|
| 首页 | 封面卡墙，点开展开 | 单页：封面大图 + 团信息，「招募中」的角色排在最前、直接点报名，下面是已定阵容 |
| 缺人看板 | 按团分组 | 只有一组 |
| 后台 | 新团、团排序 | 「加一个团」（加了以后自动变多团）、「活动 / 团信息」 |
| 海报 | 竖版 + 宽版 | 竖版 + 单团卡片 |

想从单团改成多团，在后台点「加一个团」就行。想一直保持多团界面（哪怕暂时只有一个团），把 `mode` 设成 `multi`。
