## 2026-11-14　单团一图流：不再是「只剩一个团的多团版」

**看到** 单团（Kanon 9 席 + 摄影 / 后勤）出的 master 是一张白卡：上面一条封面标题条、下面 5+4 张名牌卡、再下面一块工作组卡。
排法本身没错，但一个团的时候「团」这层容器就是整张图，白卡、标题条、人数胶囊都在重复说「这是一个团」，读起来像多团版删到只剩一个。

**判断** 多团版式的骨架是 section = 一个团，单团没有「团与团之间」要分，骨架该换掉，而不是给 section 调参数。招募海报真正要露的是：作品是谁（封面）、还差几席（进度）、每一席是谁 / 还空着（阵容）。

**改动**

- `poster/build.py`：`single()`（工作组不算另一个团，和 `server.mode()` 一致）；`master()` `portrait()` 单团时转给 `lineup()`；`social()` 也改走 `lineup()`（单团时带工作组署名）。
  `lineup()`：封面（或团长传的 `poster.hero`）铺满顶部，小封面按放大倍数轻糊；kicker = 活动名 + 日期（活动名和团名相同就不重复）；进度条 +「已定 N / M 席」；
  阵容网格 `.lu-cast` 用负 margin 压住封面下沿；工作组是一行 `.lu-credit`；日期地点有才画 `.lu-foot`。
  `lu_cols()`：列数优先让最后一行不留孤零零一张（9 → 5+4，6 → 3+3）。`render()` 的「标题条铺满」断言在没有 section 时报 `—`，不报 `full`。
- `poster/poster.css`：`.lu-*` 一套，三个画布只换尺寸变量。补了这次接着做时看到的两处：
  - 方图里「招募中」胶囊被挤成两行（`招募 / 中`）→ `white-space:nowrap`；
  - 没有日期地点时最后一块是工作组署名，导出图贴着下沿 → `.lu:not(:has(.lu-foot)){padding-bottom:var(--end)}`，三个画布各 96 / 80 / 64。

**验证**

- 用当前 instance 的拷贝重建：master 2400×2397 / portrait 1200×2465 / social 1080×1343，`still clipped: none`，三张逐张看过；网页版 `master.html` / `portrait.html` 里没有残留 `file://`。
- `tests/test_poster.py` 加 `SingleLineup` 8 条（不开浏览器，拦下 `render()` 看 HTML）：没有 section / 名牌卡、席位和空缺数对、进度文字对、工作组是署名、social 同构、kicker 不重复团名、没有日期不画页脚、列数不留单张。145 条全过。

**边界**

- 9 席只配上 3 张立绘时，空着的 6 席是虚线框 / 相机位，整张图偏空——这是名单配图的问题，不是版式问题（`map.json` 里就 3 条）。
- `wide` 仍只有多团才生成；单团要投屏就用 master。
- 本机 `.venv-poster` 的 Playwright 版本和缓存里的 Chromium 对不上（要 1255、装的是 1248），这次用 `--chrome` 指向系统 Chrome 跑的；`playwright install chromium` 一次就好。

## 2026-11-14　阵容版的三处「看得见才算数」

**看到** 阵容版出来后把三张图打开看：立绘确实压进了封面 19%，但那段正好是白霜最浓的地方——立绘顶边落在 hero 的 79–81%，霜从 54% 起、到那儿已经盖了约 55% 白。结果是压进去的那圈边看不见，读起来还是「卡片浮在雾上」，设计要的「从画里站出来」没兑现。进度条只剩前 1/3 的实心白（33% 填充正好在浅米色封面上消失），后面那段留白轨道跟糊底图混成一片，像一条画歪的装饰线。

**判断** 这不是参数没调好，是两个变量的作用区间撞在一起：`--ov` 把立绘往上抬，`.lu-hero:after` 的中段正好在同一个位置把底图洗白。两条路——抬立绘会撞标题（标题块占到 hero 的 45%），收霜更稳。进度条则不是「再亮一点」的问题：实心白压浅封面永远不够，得靠**轮廓**而不是填充来量出还剩多长。

**改动**

- `poster.css` `.lu-hero:after`：46% → 32%，峰值 80% → 82%。立绘顶边落到霜的 ~30% 处，画在立绘背后还看得见，压在纸面前也还是软的。
- `poster.css` `.lu-prog .bar`：`rgba(255,255,255,.34)` 实底 → `.20` 稀底 + `inset 0 0 0 1.5px` 实白描边 + 外投影。未填段靠一圈白线量得出来，浅封面深封面都成立。
- `poster.css` `.lu-kicker:empty{display:none}`：活动名等于团名、又没日期时 kicker 是空 div，仍占 30px 行高，标题会莫名下沉一截。
- `docs/poster.md`：`social` 不再叫「方图」——实际 1080×1343，是 4:5 竖图。

**验证** 三张重出：master 2400×2397 / portrait 1200×2545 / social 1080×1343，`still clipped: none`，逐张打开看过；进度条与封面下沿各做了改前/改后同框裁切对比（亮段实测 66px = 33%，轨道全长 200px 都能描出来）；145 条单测全过。

**边界** 霜收薄之后，封面下沿在左右页边（没有立绘遮挡的地方）比之前略微可见一点。底图本身就是 460px 放大 5 倍，再薄就要看见块状噪点，只能停在这里——要更干净得上高清底图（`site.json` 的 `poster.hero`）。

## 2026-11-14　重跑部署流程：验证层和产品各说各话

**看到** 从零跑 `lab.py smoke --via wizard --poster`，连跑三轮，每轮红的东西都不一样：

1. 一图流没生成。日志一行：「这台机器还没装依赖，跳过」——沙盒按 `EXCLUDE` 不带 `.venv-poster`，可团长的机器上是带着的。
2. 一图流生成了，但「竖版画布比横版窄」判 `量不到px`。
3. 第三轮只剩一条真失败：Bangumi 不通，月宫亚由 4/5。

**判断** 前两条都不是产品坏了，是验证层自己失准：

- **沙盒不像真机。** 排除 `.venv-poster` 是为了「干净仓库」，但一图流本来就靠仓库里那个 venv —— 于是 `--poster` 每一次都因为「没装依赖」而假失败，而这个假失败长得和真失败一模一样。
- **哑掉的断言比没有更糟。** 「竖版画布比横版窄」靠正则在 body 上量宽度，写死了 `class="portrait"`；阵容版把 body 改成 `class="portrait lu-page"` 之后正则不再命中，`w=0`，这条断言从此只会红、不再判任何东西 —— 竖版真变成 2400 宽它也是红的，看不出区别。

**改动**

- `tools/lab.py` `assert_poster()`：正则放宽成 `<body class="[^"]*\bportrait\b[^"]*"`，注释写明为什么不能写死。
- `tools/lab.py` `host_poster_env()`：`smoke --poster` 时把宿主机的 `.venv-poster/bin/python` 和 Chrome 指给沙盒，并在报告里 note 一行「海报依赖用宿主机的」。沙盒代码仍是拷贝出来的那份，只有解释器来自宿主。
- `poster/build.py` `prune(built)`：顺手删掉「这一轮不生成的那一版」。团数从多个掉到单个后，上一轮的 `wide.html` 还在，`/poster/` 的挑选脚本看见文件就用它 —— 桌面打开还是旧的多团图。这轮明确要了 `wide` 就不算遗留，不动。
- `tests/test_lab.py` +3：`class="portrait lu-page"` 和 `class="portrait"` 都要能量到 1200；真变成 2400 必须红。
- `tests/test_poster.py` +3：单团删遗留 wide、明确要 wide 时保留、多团不动。

**验证** 修完再跑：`海报依赖用宿主机的` note 出现，`竖版画布比横版窄 · 1200px` 绿，一图流三张齐；151 条单测全过（原 145 + 6 条新的）。

**边界**

- Bangumi 这边确实不通（`curl api.bgm.tv` 超时，AniList 正常），月宫亚由 4/5 是网络的锅。产品按设计降级：用 AniList 兜底、在报告里写「没法确认，网络好了重跑 names」，不算名单问题 —— 这一条没改。
- `smoke --poster` 现在借宿主的 venv，所以它不再验证「AI 会不会自己装依赖」。那条路由 `lab.py sandbox` + 真会话去走，别混。
- 单团的 `/poster/` 在横屏仍然落到 `master`（2400×2397 的长卷，要滚），没有再出宽版；这是上一条记过的取舍。

## 2026-11-12　「表里没有」不等于「名单写错了」

**看到** 同一份名单、同一条命令，20 分钟内两个结论：

```
00:02  PASS 名单里 5 个名字都绑到了角色（5/5）（来源 Bangumi）
01:00  FAIL 名单里 5 个名字都绑到了角色（4/5）（来源 AniList，Bangumi 不通）
       FAIL 立绘配齐（4/5） · 名字没绑上 1 个（名单问题，改名单或后台手选）：Kanon/月宫亚由
```

`月宫亚由` 是 Kanon 的女主，名字没错。AniList 那张角色表里只有 `月宮あゆ`（汉字改写成假名），代码按「假名改写一律不猜」不绑它——这是设计，不是缺陷。缺陷是**这句话把它报成了名单问题**，`cause` 还是空的。单独跑 `artsearch.py names` 更直接：`✗ 月宫亚由　作品角色表里没有这个名字`，底下还劝「改好名字再导入」。

翻代码找到两个缺口：

1. `art_bind_run.json` 只存计数（`missing: 1`），不存「哪个名字、按哪张表判的」。事后谁也不知道那 1 个是 Bangumi 说的还是 AniList 说的。
2. `net` 的定义是「**所有**名字都 unknown 才算不通」。核对跑到一半断网、只坏了一部分时 `net` 仍是 `true`，于是断言把剩下的算成名单问题——和 11-11 S1「必填项被当成不能报名」是同一类错：**断言自己判错，比没有断言更糟**。

**判断**

- 「表里没有这个名字」的含义取决于**那张表是什么表**。Bangumi 有 `name_cn`，中文名查得到；AniList 只有 native 名，假名化的必然查不到。这是表的边界，不是名单的边界。
- 只改措辞不够：要分类就得有数据。先让核对结果自己带上「哪个名字 / 什么状态 / 哪张表」，断言再照它分。
- 「没法确认」不该让 check 变绿——图确实没配上，FAIL 是对的。要改的是 `cause` 和那句解释：让团长知道**现在该等网络，不是该改名字**。

**改动**

- `server/artsearch.py`：`bind_run_save()` 增加 `unbound: {"团|角色": {"state", "src"}}`；`bind_group()` 在 AniList 表下把 `why` 写成「AniList 的角色表里没有这个名字（这张表只有日文名，可能只是写法不同）」；`names` 的尾注在 Bangumi 不通时不再说「改好名字再导入」，改成「网络好了重跑一次」。
- `tools/lab.py:unbound_kind()`：`roster` / `weak` / `net` / `none` 四类，`assert_bind` 与 `assert_art` 共用。`assert_art` 的缺失改成四个桶；`cause=env` 只在「没有一个名字真的对不上、也没有没核对过的」时给。
- `tests/test_lab.py`：新增 `Kinds`（4 条）+ `Art` 里 3 条（Bangumi 不通 → 没法确认 + env；Bangumi 通 → 名单问题且不归环境；部分 unknown → 断网）。124 → 128。

**验证**

- 01:06 再跑 `smoke --via wizard`（Bangumi 仍不通）：

  ```
  FAIL 立绘配齐（4/5）· 没法确认 1 个（Bangumi 不通，判它的是 AniList 的表，只有日文名；网络好了重跑 names）：Kanon/月宫亚由
  ```
  `cause=env`（改之前这条是 `cause` 为空、措辞是「名单问题」）。
- `names` 实测输出：`✗ 月宫亚由　AniList 的角色表里没有这个名字（这张表只有日文名，可能只是写法不同）`，尾注「网络好了重跑一次，或后台手选」。
- 128 个单测全过；`smoke` 1.0 秒 ALL PASS。

**边界**

- `weak` 是按**名字**判的，不是按整次核对：`unbound` 每条自己记 `src`。一次核对里 Bangumi 中途恢复，前半段走 AniList、后半段走 Bangumi，也能分开说。
- 「没法确认」仍然是 FAIL。断言不替团长决定「少一张图能不能接受」；后台手选过的会写成 `by:manual`，那才叫人工确认过。
- 老沙盒的 `art_bind_run.json` 没有 `unbound` 字段，退回按 `sources` 判；更老的（11-11 之前）连 `sources` 都没有，保守当 `roster`——宁可多说一句「像是名单问题」，也不替它开脱。

## 2026-11-12　验证的两个缺口：配图零断言，沙盒跑旧代码

**看到** 回看这份记录的「还没做」，有两条一直没动、但都属于**验证能力**，不补的话后面每一轮的结论都要打折：

1. `assert_poster` 只判 `master.html` 在不在，配图没有任何断言。少三张立绘也 ALL PASS，靠人眼看出来。AGENTS.md 第 3 步明明写了「立绘 N 张应该等于可配图的角色数，不要看着差不多就报完工」——这条要求 AI 做，lab 自己却不做。
2. 沙盒是拷工作区的快照。建完沙盒再改主仓库，`check` 验的就是旧代码（R2 真发生过）。反过来，部署的 AI 在沙盒里改了代码，`check` 也看不出来——它可能修了真 bug，也可能绕过了断言。

**判断**

- 配图断言的难点在「阈值」，待办里因为这个一直没做。其实不需要阈值：**要求全配齐，但缺的逐个归因**。名字没绑上（`art_bind.json` 没有 id）是名单问题，重试多少次都配不上；绑上了但没图是下载失败，多半是网络。这和第 2 条原则是同一件事，`assert_bind` 已经把名字那一半做了，这里只是接上图那一半。
- 只看 `map.json` 有没有记录不够——记录在、文件丢了也算没配上（测试里专门造了这种）。
- 全是下载失败、或那次核对两个库都不通，`cause` 记成 `env`；只要有一个名字没绑上，就不归环境——否则名单问题会躲进「网络不好」里。

- `tests/test_lab.py`（新）：lab 自己的断言第一次有了单测。11-11 S1 已经证明断言会判错，判错比没有断言更糟。

## 2026-11-11　从 keyroster 同步：海报的字，和海报的旧

**看到** keyroster（同一个人的常驻团片站）比 castcall 早分叉出去，之后它又踩过两个海报的坑：

1. 窄屏（iPhone）上长角色名会被切掉最后一个字。原因不是字多——构建时按 Chrome + 本机 Noto 量到「刚好放得下」（`scrollWidth > clientWidth + 1`，容差 1px）。iPhone 上字体回落到系统宋体、再叠 `zoom` 的亚像素取整，那点余量就没了。
2. `.role` 写的 `font-family:"Noto Serif CJK SC",serif`。iPhone 没有 Noto，落到裸 `serif`，而 iOS 的中文 serif 实测给的是**黑体**。于是名字本该宋体却变黑体，而且黑体墨迹更顶格，行尾那个字看起来像被削了一角。

顺带发现 castcall 自己还有第三个：海报是**建站时**生成的，之后团长改名册，海报一直是上一版，而后台没有任何提示。

**判断** 前两个是能直接搬的（自包含的 CSS/JS），第三个不能照搬 keyroster 的做法：它靠 launchd 每 10 分钟拉一次线上 `/api/data`、比 sha、`git commit` 再 deploy——那套前提是有台常驻机器和一个 git 仓库。castcall 的部署形态是团长自己的电脑或一台小 VPS，**反复开 Chrome 会抢内存**。所以这里只做「知道它旧了」，把重不重建交给团长按一下。

**改动**

- `poster/build.py:render()`：构建期不再量 `scrollWidth`，改成克隆一个 `max-content` 节点量**文字本身**的宽度，收到可用宽度的 97%（留 3% 余量）。踩过的坑：`scrollWidth` 在放得下时等于 `clientWidth`，拿它乘系数会把所有卡片判成溢出。
- `poster/build.py:FIT_JS`：网页版再加一道**运行时** `fitText`——`document.fonts.ready` 之后、每次 resize，按**当前设备自己的字体**再量一遍，超了就继续收（记住 CSS 原字号，下限 45%）。
- `poster/build.py:web()`：补 `html{-webkit-text-size-adjust:100%}`，挡掉 iOS 的 font boosting。
- `poster/poster.css`：宋体栈补到 `Songti SC / STSong / SimSun`，黑体栈补到 `PingFang SC / Hiragino Sans GB / Microsoft YaHei`。
- `server/server.py:poster_stale()`：名册 / 站点 / 立绘映射任一比 `poster/master.html` 新就是过期。只看这三个文件，不扫 `uploads/`——传一张没人用的图不该说海报旧了。没生成过不算过期（那是 `ready` 的事）。
- `server/server.py:poster_versions()` + `POSTER_BACK`：导出的 `?v=` 从 `Date.now()` 改成**图自己的 mtime**，同一版重复导出命中缓存，重新生成后 URL 自动变。
- `server/server.py:H.end_headers()`：`/poster/cache/*` 永久缓存（文件名就是内容 hash），导出图改成 `?v=` 门控（以前是 blanket `no-store`，每次导出重下 20 MB）。
- `web/edit.js:posterBtn()`：「生成一图流」按钮上挂一个「旧」标记，重建完自动消失。

**验证** 造一份 18 字角色名 + 15 字成员名的名册重建：

```
narrow {'n': 8, 'clipped': ['这个是特别长的角色名字…'],
        'shrunk': ['这个是特别长的角色名字… 42->18px', '一个特别特别长的coser名字 30->16px']}
```

运行时确实在按设备收字号（42→18 = 45% 下限），正常长度的名字不再有 `clipped`。单测 114 个（新增 4 个：过期判定 / 没海报不算过期 / 缓存头 / 导出 `?v=` 等于 mtime），`lab.py smoke` 0.7 秒全过，`smoke --poster` 6.3 秒生成海报。

**边界**

- **没有自动重建。** keyroster 的 autobuild 靠 launchd + git commit，castcall 不做这个。理由写在判断里：团长机器上每改一次名册就开一次 Chrome，内存扛不住，而且「什么时候生成」该由团长决定。按钮上的「旧」只是让这件事**可见**。
- 极端长名（18 字）收到 45% 仍放不下，会被切。这是下限保护：再小就看不清了。`build.py` 的日志会打出「名字太长，字号已经收到下限」，但日志在 `instance/logs/poster.log`，团长看不见——真要治，是在保存名册时拒绝超长名字，那是另一个决定。
- 网页版 `fitText` 只在**海报页面**（`/poster/*.html`）跑。名单首页的角色卡是另一套 CSS（`cast.css`），没有这个问题，也不该被这段脚本碰。
- 字体栈只加了解析失败时的兜底，**没有把字体打包进产物**。团长机器上有 Noto 就用 Noto，没有就用系统宋体——视觉不会完全一致，这是有意接受的。

### 顺带：零上下文部署暴露的三个洞

合完这批，按既定流程新建一个沙盒、让一个不知情的会话从零部署（记作 S1），外部断言抓出三件事——都不是新特性的问题，是新特性**旁边**的老问题：

1. **`init.py` 的名单核对从来没成功过。** `log=lambda *x:print('  '+x)`，x 是 tuple，`'  '+('核对…',)` 直接 TypeError，然后被同一个 try 的 `except` 吞掉，打印一行「没核对成（can only concatenate str…）」。走 CLI 建站的人看到的是「预检跑了」，其实一个字都没核。改成 `'  '+' '.join(str(i) for i in x)`，并加了一条会**故意传两个参数**的回归测试（把修复撤掉，这条测试立刻红）。
2. **后台手选立绘不写绑定表。** `POST /api/admin/art/pick` 只存图 + `map.json`，名字在 `art_bind.json` 里仍然是「没绑」。于是「人工确认」只存在于一张图上：下次名单核对还报「作品里没有这个名字」，换张图又要点一遍。现在 pick 会带上角色 `id`/`name` 并写 `by:'manual'`；自动绑的写 `by:'auto'`。断言里的「N 个自动 / M 个人工」因此才有依据。
3. **`lab.py` 的报名断言不会填必填项。** 团长把身高设成必填后，lab 只发 CN + 联系方式，400 被记成「不能报名」——把**正确行为**判成 FAIL，还连累下一条「后台读得到待审」。现在按 `site.json` 的 fields 填一份合法值；样片这种要真文件的填不了，单独 note，不连坐。

S1 最终：`ALL PASS`，`5/5 绑到角色（来源 AniList，Bangumi 不通，4 个自动、1 个人工确认）`。

## 2026-11-11　断网时名单核对等于空转，而且不留痕迹

**看到** 零上下文会话跑完一版（记作 R3），外部断言 ALL PASS、5 张立绘齐、一图流也生成了。但 `instance/uploads/art_bind.json` 不存在——而那是名单预检的产物。

- `server/artsearch.py:bind_run_save()`：每次核对照写 `instance/uploads/art_bind_run.json`（时间 / 两个库通没通 / 自动绑了几个 / 来源）。
- `tools/lab.py:assert_bind()`：据此分三态——没跑 / 跑了但两个库都不通 / 跑了有结果；并把「自动绑定」和「之后人工补的」分开报。

**踩到的坑** AniList 的 `characters(perPage:$n, sort:ROLE, role_not:BACKGROUND)` 组合直接 HTTP 400，去掉这两个参数（默认按主要角色排序）就好了。报错只有 `HTTP 400 :`，没有 message，只能二分查询才定位到。

**验证**

## 2026-11-10　名单预检：把「配不配得上图」提前到名单定下来之前

**看到** 用户的问题是「能不能在确定名单的时候就确保名单里的名字能抓到图」。原来的流程是建完站、配完图，少了几张才知道。

**判断** 光「提前检查」不够，还得**绑定**。因为搜索会漂：同一个名字，排序变了、网络变了、有同名角色了，结果就变。把名字绑到一个确定的角色 id 上，才不会。

**改动**

- `bind()` / `bind_group()` / `work_chars()` / `bind_line()`：团名找作品 → 读作品角色表 → 每个名字判 `ok` / `near` / `missing` / `unknown`，落 `instance/uploads/art_bind.json`。`auto()` 命中绑定就直接按 id 取图，**一次搜索都不发**。
- `POST /api/setup/names`：向导第 3 步的「检查这些名字配不配得上图」按钮走这里；预填完成后自动跑一次。
- `web/setup.html`：结果区按 ✓ / ⚠ / ✗ 列，`✗` 下面给出该作品实际的角色名，点一个就替换名单里的字并重新核对。
- `init.py`：`--import` 之后自动核对；`firstrun.art()` 配图前 `bind(skip_bound=True)` 兜底。
- `tools/lab.py:assert_bind()`：查「名字绑上没有」（名单问题），和「图配上没有」（网络问题）分开。

**踩到的坑** 第一版在断网时每个团各等一次 15 秒超时，向导里实测 33 秒，用户会以为页面死了。加 `bangumi_ready()` 先探一次（8 秒）后降到 6 秒。后来（11-11）这个「探不通就放弃」又被改掉了——探不通只是换个源继续，不是放弃。

**验证** 109 个单测全过；向导接口端到端 6.1 秒；`names` 退出码语义：有名字配不上 = 1。

## 2026-11-09　AGENTS.md 的举例被当成默认值

**看到** 三个并发会话，同一句话需求，长出三个不一样的站。其中一个把活动日期编成「2026-11-21（周六）」贴在页面上，还把「样片」设成必填，导致外部报名直接被 `{"error":"请上传样片"}` 拒掉。

**判断** 根因在 AGENTS.md 那句「（身高、年龄、性别、样片……都能设成选填或必填）」——括号里的举例等于一份默认勾选清单，AI 直接照抄，还自己加了「必填」。这不是 prompt 措辞问题，是**文档在给默认值**。

## 2026-11-12　一图流：没背景、单团卡片不适配

**看到** S3 沙盒零上下文部署，`check` 16 项全 PASS，但把 `master.jpg` / `social.jpg` / `/poster/` 页面摊开看，三处不对：

- `social.jpg` 下半张 60% 是空白：2 人已定时网格还是 `--cols:5`、画布写死 1080×1350，右边空两列、下面空半张。
- `master.jpg` 5 张卡只用了 8 列里的 5 列，右边 3 列空；摄影组只有 2 人却占 4 列。**卡片宽度和它占的列数没有关系**，所以人少时整块是空的。
- 页面背景就是一层淡蓝渐变 —— 因为 `poster.hero` 为空就没有底图；`/poster/` 那页还在海报下沿留一条硬边 + 一整屏空白。

**判断** 断言只能判「有没有」，判不了「好不好看」，这一轮的问题全在画布上：

1. **一图流是招募海报，空席位是最该露的信息。** 以前把「待定」整张卡藏掉（`settled()`），5 席定 2 席就只剩两张卡，版面空一半，还看不出在招人。改成画出来：虚线框 + 立绘压暗 + 名字位置写「招募中」，标题条的人数变成「2/5 人」。CSS 里本来就有 `.vac` 这条规则没人用，说明当初想过。
2. **列数跟人数走，不跟画布走。** 每个团占 8 列中的「席位数」列，卡宽恒等于 1 列；单团卡片 `--cols = min(5, 人数)`。
3. **没有底图不等于没有背景。** 团长没传 `poster.hero` 时拿第一个团的封面当底——但不能直接铺：封面只有 400–600px，铺到 2400 宽是「放大」，会看到块状噪点和人脸。所以放大到 280% 再 blur 96px，糊成一片色场；标题区同源取色（blur 110px、半透明）。有 hero 的团长走原路，一点不变。

**改动**

| 位置 | 改了什么 |
|---|---|
| `poster/build.py` `card()` / `section()` | 空席位也出卡（`.vac`）；人数 chip 改 `2/5 人`；`span()` 由「≤4 就 4 列」改成「占几席就几列」 |
| `poster/build.py` `hero()` / `page()` / `title()` | 没 hero 就回落到第一个团的封面，并标记 soft：整页加一层 `.wash`，标题带加 `.tbg.soft` |
| `poster/build.py` `social()` | `--cols` 按人数取（≤5 取人数，最少 2 列）；画布高度改为随内容（`min-height:1080`）；封面 <900px 宽时给 `.ban` 加 `soft-up`（糊 1.6px，放大后的块状噪点看起来像「背景虚化」） |
| `poster/build.py` `web()` / `FIT_JS` | 背景两层不进缩放壳、改 `fixed` 铺满视口；海报竖直居中用 `margin:auto`（内容超高时 auto 退成 0，不会切顶）；`#kr-poster-clip` 抬到 `z-index:1` |

**怎么验** 造三个实例：A 5 席全定、B 2 席已定、C 1 席已定，各出一套 master + social，逐张看图；再同步进 S3 沙盒，走后台按钮重建，用 390 / 1440 两个宽度打开 `/poster/` 截图。

修的过程中踩到的三个「看着像 CSS 没生效」：

- `.wash` 自己带 `background-image` 是错的：`::before` 糊开了，元素本身却按默认 `repeat` 把 460px 的封面平铺了一遍，底下就是一片重复的人脸。图改走 `--img` 变量。
- 网页版背景盖住海报：`#kr-poster-scale` 上的 `zoom` 让整张海报落进一个 `z-index:auto` 的层，`z-index:0` 的 `.wash` 反而在上面——整页像蒙了层雾。
- 海报上沿那条硬边来自 `.tov`，不是 `.tbgs`：把 `.tbgs` 藏起来接缝还在，藏 `.title` 才消失。

**边界**

- 封面糊得再狠也补不回细节。团长的封面只有 460px 宽时，`social` 铺到 1080 就是 2.3 倍放大，只能靠「虚化」让它看起来像故意做的。真在乎清晰度，得让团长在后台传自己的高清封面（`poster.hero` 现在还是纯手填，没做上传引导）。
- `social.jpg` 不再是固定 4:5：人少时是 1:1，人多才会变高。发小红书会被平台加边，发群没有影响。
- 空位是否要上海报是**团长的决定**，不是技术决定：想让它变回「只画已定」就要一个开关（`site.json` 里加 `poster.vacancies:false`），这一轮没做，因为默认值只能选一个，而招募场景下人少是常态。
- 网页版在手机上仍是「整张缩到一屏」的小图（`zoom = 视口宽 / 2400`），只是现在居中、背景铺满。要让手机上直接看清字，得改成「按卡片宽度适配 + 横向滚动」，是另一个决定。

## 2026-11-12　标题条：从「贴纸」到「铺满」

**看到** 上一轮改完之后，团块的标题条长这样：左边一大片纯品牌色，右端一块方形封面，中间一道看得出的分界。功能上没问题——封面在那儿、标题也在那儿——但看着像在色块上贴了张缩略图。

**判断** `FRAME_JS` 不是写错了，它当初是给另一件事写的：保证 `cover_focus` 框里的人**完整可见**。做法是把封面缩到刚好装下这个框（`sFit`），再挪到标题右侧那段空位里，剩下的宽度交给品牌色渐变去填。竖版封面裁成小框时这没错，可一旦这张图承担「标题条的底」这个角色，就全错了——**底图不铺满就不叫底**。

铺满的代价得先算清楚：460×611 的封面塞进 1400×290 的横条，纵向只能露 15%。所以「铺满」不是把 `background-size:cover` 一写了事，裁在哪儿才是重点——

- 取 focus 框**正中**对位，正好把头顶切掉（第一版就是这么干的，出来一排「无头半身像」）。
- 取 focus 框**上部 15%** 对位，人脸落在条的上三分之一，头顶保得住。

**改动**

| 位置 | 改了什么 |
|---|---|
| `poster/build.py` `FRAME_JS` | 去掉 `sFit`/`cov` 两条分支，恒 `s = max(W, Hb*ar)`：横向永远盖满整条。对位 `x`/`y` 由 focus 框算完再夹回图内，`y` 取框上部 15%。`tall` 分支的二次放大一并删掉（已经 cover，没有意义） |
| `poster/poster.css` `header:after` | 渐变从 48% 拉到 72%，中间插一个 24% 的停靠点。它原来只管「给标题托一层色」，现在承担「色块 → 照片」的过渡，收得太早就变成一条色带 |
| `poster/build.py` `render()` | 加一条画布断言：每个 `section>.bg[data-face]>.im` 必须横向盖满 section，否则日志打 `cover band: Kanon ← 标题条没铺满` |

**怎么验**

- 造 A（5 席全定）/ B（2 席已定）两套出 master，再做一个**横版封面实例**：一张左红 / 中绿 / 右蓝的 1200×600 图，好处是横向裁到哪儿一眼能看出来（答案是居中，三块都在）。wide 版另验。
- 反向验证断言：把 `s` 改成 `W*0.2`（模拟退回小方块），日志立刻变成 `cover band: Kanon ← 标题条没铺满`；恢复后 `cover band: full`。
- 同步进 S3 沙盒，走后台按钮重建，再开 `/poster/` 看线上效果。128 个单测、`smoke`、`smoke --poster` 全过。

**边界**

- **竖版封面铺进横条，纵向必然裁掉七成**。头顶保得住是挑对位挑来的，不是无损——想要完全不裁，只能不铺满。
- 标题的可读性现在靠 `header:after` 的品牌色渐变 + `text-shadow`。**浅色封面（白底、高调照片）上白字会掉进图里**，要更稳就得给标题加底板，可那又回到「贴块板子」。这一版选择让位给画面。
- `cover band` 只判「有没有盖满」，判不了「裁得对不对」——人脸在不在条里、有没有拦腰切，这需要人脸检测，超出这一轮。
- 摄影 / 后勤这类没有封面的组走 `.bg.sky`（蓝色渐变），不参与这条断言，也不该参与：它们本来就没有图可铺。

前端的 `checkNames()` 只发 `{names,title}`，不发 `source`；`preview` 那条发了，所以预览一直好好的。

**改动**

| 位置 | 改了什么 |
|---|---|
| `server/server.py` `setup_post()` | `src = b.get('source') or ('paste' if text.strip() else 'blank')` |

熔断是模块级的，所以用完 `finally` 还回去——不然向导里核一次，同进程的后台「找立绘」就再也不问 Bangumi 了。

**顺带修的第三个（测试装置的）** `smoke --via wizard --poster` 每次报「一图流生成了 ✗」+「firstrun 收尾跑完了 ✗」，

## 2026-11-15　README 的定位：AI 代跑，手把手教程是验收手册

**问题** 图文 README 写完后通篇是「打开终端、复制这条命令、点这个按钮」，读起来像要求团长自己敲完九步；而仓库本来就是按「AI 助手来跑」设计的（`AGENTS.md` 是给 AI 的手册、`skills/` 两个技能、`lab.py blind` 验的就是零上下文助手能否按文档走通）。上一版只在文末藏了一句「交给 AI 助手时……」，主次反了。

**判断** 手工教程不能删——它是团长看懂流程、检查 AI 做没做对的依据；但必须先说清「你其实不用自己动手」，否则小白会被一整页命令行吓退。所以不动九步正文，只在流程图后面加一段醒目结论 + 一个专门小节。

**改动** `README.md`：开头高亮「下面这些步骤基本上都能让 AI 跑完」；新增「最省事的做法：整件事交给 AI」，含可直接复制的提示词、「AI 自己会做 / 必须你拍板」对照表（名单、日期地点、报名字段、密码、要不要上线）、全权代办走 `init.py` 的边界、三条外部验收证据（`roster.json` / 立绘 N 张 / 第 5 步四项 + `/api/health`）；文末那节收敛成「没有浏览器：命令行一次做完」并交叉引用，避免两处重复；文档索引里点明 `AGENTS.md` 就是 AI 代跑时读的。

**验证** 14 张图、全部文档链接、3 个内部锚点均可解析；纯文档改动，没有动代码，也没有重新发布（线上代码与上一轮一致）。

**边界** 「基本上」不是「全部」：只有团长才知道的事实、管理密码、上线与否仍要人给，文档里逐条列了，没写成「全自动」。`lab.py blind` 有这个能力但本轮没跑（`lab.py list` 里没有结果），文档只说它有这个用途，没写「已验证通过」。

## 还没做（有判断，没动手）

| 事项 | 为什么值得做 | 为什么还没做 |
|---|---|---|
| **`net.py` 录制 / 回放** | 现在的假数据比真数据整齐，所以「只认日文名」这类 bug 在测试里永远抓不到。录一份真实响应当夹具，`CASTCALL_NET=replay` 时不发请求 | 原来卡在 Bangumi 一直 502；11-12 它在线跑通了（5/5 自动绑上），**前提已经有了**，下一个该做的就是它 |

| **`init.py --from brief.json`** | 把 AI 的自由度收成输入：brief 里只有用户说过的事实，没给的字段代码不写。再配一条「编造检测」断言 | 得等验收标准先稳住，否则只是把不确定性挪个位置 |

| **锁版本 + CI + `init.py doctor`** | 只有 `requirements-poster.txt` 且是 `>=`；没有 CI；冷环境「一图流装不装得上」靠运气（实测 2/3） | 属于工程卫生，不影响单机正确性 |

## 四条原则（从这些坑里长出来的）

1. **断言在外部。** AI 说建好了不算数，脚本自己看文件和 HTTP。自述和结果之间的差距，就是这个项目最大的风险来源。
2. **失败要分类。** 「名字对不上」是名单问题，现在就能改、改完永久有效；「图下载失败」是网络问题，稍后重试就行。混在一个「配了 N 张」的数字里，就只能靠猜。
   分之前先问一句**判它的那张表有没有资格判**：AniList 只有日文名，它说「表里没有」不等于名单写错（11-12 两天里同一份名单 5/5 和 4/5 都出现过，差的只是 Bangumi 通不通）。
3. **宁可空着，不配错图。** 错字只差一个字且候选唯一才认；差两个字且是假名改写的（月宫亚由 / 月宮あゆ）一律不猜，列表给人点。
4. **断言全过 ≠ 交付能看。** 断言判的是「有没有」：立绘在不在、海报有没有生成。它判不了「5 席定 2 席时整张图空一半」。每一轮都得把产物**打开看一眼**，看见的那些才是下一轮要修的——11-12 这一轮的三处（没背景、空位不画、单团卡片不适配）没有一处能让断言变红。
